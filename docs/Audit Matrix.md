# FedORBIT Pre-Experiment Audit Matrix

**Exact requirement count: 250**

## Purpose and scope

This matrix is a pre-experiment verification contract for FedORBIT. It is designed for a later executing agent to determine whether the repository is scientifically and technically ready to begin the registered experiments. This file does **not** record an audit result and does **not** authorize scientific experiment execution. The later audit may run genuine short/non-evidence commands and real preprocessing, but it must stop before evidence-bearing experiment execution.

The authoritative scientific basis is the FedORBIT roadmap. Repository structure is implementation-flexible when equivalent semantics and wiring are preserved. Real measured dataset facts may differ from historical expectations; such differences are evaluated as evidence-backed empirical deviations rather than forced to match obsolete estimates.

### Explicit pre-experiment prohibition

- Do not run development, confirmatory, ablation, robustness, boundary, generalization, scalability, statistical-synthesis, or evidence-classification scientific workloads while executing this audit.
- Do not inspect principal TEST outcomes to tune code, thresholds, methods, grids, seeds, baselines, statistics, or claim criteria.
- A genuine isolated `fedorbit smoke` is permitted only under its roadmap contract; real `fedorbit preprocess` is mandatory when the registered raw data are available.
- Experiment workflows must still be inspected, counted, and traced prospectively from the actual production entry point to deepest leaves and output artifacts.

## Authority hierarchy

1. **Scientifically authoritative:** equations, algorithm semantics, information/resource restrictions, chronology/leakage rules, experimental design, methods/comparators, grids, metrics, statistics, seed roles, claim criteria, and failure semantics.
2. **Empirically amendable:** observed client/row/class/support/campaign/time-range/runtime/hardware properties and unavailable secondary data/conditions. Deviations require measured evidence and must not be manufactured away.
3. **Implementation-flexible:** filenames, internal module boundaries, helper placement, class names, libraries, caching mechanics, and parallelization, provided the scientific contract and complete workflow wiring are preserved.

## Status and severity definitions

During execution, replace the `—` status placeholder with exactly one of: `PASS`, `FAIL`, `PARTIAL`, `MISSING`, `UNWIRED`, `DEAD_CODE_CANDIDATE`, `JUSTIFIED_EMPIRICAL_DEVIATION`, `JUSTIFIED_ARCHITECTURE_DEVIATION`, `BLOCKED_BY_PRE_EXPERIMENT_STATE`, `NOT_APPLICABLE`.

Severity is one of `BLOCKER`, `MAJOR`, `MINOR`. `BLOCKER` means experiments must not begin until resolved or scientifically downscoped by an authoritative rule. `MAJOR` means a material technical/scientific readiness defect. `MINOR` means a non-blocking quality issue that still requires disposition.
