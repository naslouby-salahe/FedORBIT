### Locally available physical IoT candidate: Edge-IIoTset raw captures (screened 2026-09-30)

The shared raw-data tree contains the Edge-IIoTset bundle: ten per-sensor benign PCAPs, fourteen attack-type PCAPs, and prepared feature CSVs. Its local README grants academic research use and requests citation of the dataset paper. The primary paper describes non-continuous normal and attack collection during Nov 21, 2021–Jan 10, 2022; PCAP capture was limited to at most three continuous hours and collected from Raspberry Pi 4 edge-server interfaces. A metadata-only scan of the 24 local PCAPs found the benign packet timestamp envelope Nov 21, 2021–Jan 5, 2022 and the parseable attack-record envelope Nov 24–Dec 27, 2021. One vulnerability-scanner PCAP has a malformed record header after 265,827 records: it declares a 136-MB packet with only 28.7 MB left in the file, so its tail and final time are unverified. A packet-header census of all fourteen attack PCAPs against the paper's Table VI sensor IPs found only the DHT11 sensor `.101` among those addresses; it appears mainly as a source, with 35 destination records in Port Scanning and 12 combined in Backdoor/Ransomware. The other listed sensor IPs do not appear. Most records in the server-oriented web, password, upload, SQL, ransomware, and flood captures are between attacker `.170` and edge server `.128`. The DHT11 normal PCAP spans Nov 21–Dec 20; `.101` appears in attack-file records Nov 24–Dec 5. A targeted header review found that the Port Scanning capture has 35 `.101`→`.128` UDP packets and 35 reverse `.128`→`.101` ICMP packets; the `.101` destinations in Backdoor/Ransomware are TCP packets from source port 5900 on `.128` to high client ports on `.101`. These headers show no `.170`-to-`.101` traffic. In the MITM capture, IPv4 packets involving `.101` are mDNS/LLMNR or broadcast discovery; ARP records show `.101` resolving `.128` with the Table VI sensor MAC, not an observed spoof claim. The paper separately lists `.101` among MITM attacker addresses. These headers do not support `.101` as an attacked physical client, and attack-file membership is not a per-record attack label. The paper describes shared edge-server interfaces. The prepared ML/DL CSV path drops `frame.time` and host-address fields and shuffles rows; the production loader also rejects the configured Edge-IIoTset event time as not timestamp-shaped. Raw PCAPs may still permit some flow-level attack reconstruction, but this capture screen does not establish same-sensor attacks or an eligible support-to-attack test. Treat Edge-IIoTset as unvalidated for this study unless an independent row-level target/label crosswalk is recovered ([dataset paper](https://doi.org/10.1109/ACCESS.2022.3165809); local academic-use notice: `data/raw/Edge-IIoTset/Readme.txt`).

This is a highly selected population and cannot rescue the intended Linux comparison.

### Exact-group model-impact diagnostic

A bounded ToN Network model POC scanned all 23 configured shards (22,339,021 rows), inferred the production behavioral schema, and retained a seeded uniform-priority sample capped at 1,200 rows per class (11,852 rows across the 10 available classes). Five deterministic stratified 80:20 splits (seeds 4129–4133) shared the same sample and a fixed-seed 40-tree Random Forest; each method used the same test rows within a split. Mean macro-F1 (sample SD across splits) was 0.9426 (0.0098) for ordinary row splitting, 0.9245 (0.0130) after removing training rows whose exact normalized feature vector occurred in test, and 0.9391 (0.0066) after a class-wise random purge matched to the exact-group-purged training counts. The paired exact-purge minus row-split difference was −0.0181 (SD 0.0112), negative on all five splits; exact-purge minus same-size random-control was −0.0146 (SD 0.0123), negative on four of five. Exact-group purging removed 600–653 of 9,481 training rows (6.3–6.9%) and 79–96 overlapping vector groups per split. Balanced accuracy showed the same ordering (means 0.9430, 0.9253, and 0.9395, respectively). Each test split contained only 11–16 rows in 10–15 full-release conflicting-label groups. The sample is class-stratified rather than row-population-weighted, and five splits of one sample are not independent data replications. These diagnostics suggest exact-vector overlap affects this sampled classifier, but do not estimate population performance or attribute the effect to contradictory labels. It purges exact vectors only (not near-duplicates), has no global-future split, and does not reproduce the 2026 paper's unknown feature key. The current adapter infers numeric-versus-categorical feature roles using observed values from the full release before the split; this mirrors production schema resolution and is unsupervised, but this POC does not test a train-only role-inference pipeline. A bundled Network feature-description workbook provides declared `Time`, `String`, `Number`, and `Boolean` types for the 46 canonical fields, and these field names match the common raw header. One of 23 shards adds a `uid` column; production reconciliation drops it because it is an identity field. The adapter does not currently consume the workbook, so metadata-driven roles are a feasible follow-up if ToN returns to scope, not the key used by this measured POC. Reproduction script/output: `ton_group_leakage_model_probe.py` / `.json` under the ignored POC directory.

The Windows probe found 35,975 rows and 35,975 duplicate groups (all groups singleton), yet global time ranges for the split buckets overlap substantially: TRAIN spans 2019-04-02 to 2019-04-29, while TEST spans 2019-04-24 to 2019-04-29. For example, Password TRAIN starts on 2019-04-26 at 13:47 UTC, after DDoS TEST starts that day at 05:13 UTC. The per-class partitions are ordered, but the combined test set is not a global future holdout. ### Global-time class-support POC (2026-09-25)

To check whether class-wise chronological assignment can be replaced by a future-only split, a lightweight raw-file scan projected only each configured timestamp and multiclass-label field for Windows 10 Host (35,975 rows) and Network (22,339,021 rows). Within each component, it cut the **unfiltered** rows at the configured global time quantiles 0.55/0.70/0.80/0.90, keeping equal timestamps together. This screen did not remove conflicting feature groups or purge exact-duplicate groups crossing a boundary; it did not train a model.

The result rules out an all-label forward-time split under this population: **none of the eight Windows-shared attack labels appears in all five global-time bins in either component.** Windows Host `dos` and `injection` occur only in the second bin, `mitm` and `xss` only in the final bin, while `ddos`, `password`, and `scanning` occupy only subsets of the bins. Network `scanning`, `dos`, and `injection` occur only in the first bin; `ransomware`, `backdoor`, and `mitm` only in the last; the remaining shared attacks also miss at least one bin. Normal spans all bins. Thus the existing per-class split preserves attack support by placing observations from each attack campaign into every nominal split, but those sets do not form a global future holdout. Removing the contradictory Network groups (0.973% of rows) cannot turn the absent class/time cells into a representative all-label future test; any narrower retained-label estimand would need to be declared separately.

The component-wise cutoffs fall between 2019-04-23 and 2019-04-27 UTC, while individual Windows and Network attack windows are tightly localized and largely align by campaign. The raw counts, class timestamp ranges and cutoffs are in ignored `ton_network_global_time_support.json`; the projected-column POC is `ton_network_global_time_support.py`. The check does not construct one shared calendar cutoff across modalities or quantify cross-boundary duplicate-group mass, but it is sufficient to reject the former all-label future-generalization claim for either component under global chronological partitioning.

## Synthetic protocol wiring audit (not experiment results)

Source/config inspection shows substantial reusable synthetic machinery, but not the full selected algorithmic protocol:

* Exact separator validation is registered for 17 support/pattern cells × 10 seeds × 100 instance indices = 17,000 instances with exhaustive orbit truth and certificate checks. It is a correctness gate, not method-utility evidence.
* The coupling factorial has 4,050 nominal seed/condition cells, but the producer fixes `instance_index=0`, so it currently draws only one instance per cell/seed. It persists fixed-action coupling, robust candidate-set value gap, upper-bound diagnostic, and support; no action-disagreement or map-conditioned regret distribution is stored. Generation failures now stop with the failed cell's condition, support, seed, and instance index; they are no longer silently skipped.
* Common-action, robust-compromise, and map-dependent fixture families each target 50 fixtures per seed (500 nominal worlds per family). These are rejection-sampled structural fixtures, not random samples from a factorial population. The map-dependent producer used to accept value-of-information cases without requiring different map-conditioned winners. This was corrected in `src/fedorbit/experiments/synthetic.py`; its focused regression test now checks both distinct winners and the value floor. Existing persisted diagnostics still do not include action vectors or action-disagreement rates.
* The exact-solver benchmark has 15 node counts × 2 block patterns × 3 supports × 10 seeds = 900 nominal cells, one generated instance per cell/seed; exhaustive truth is available only below the configured orbit-size cap. Dense-CCP is a heuristic.
* The weak-signal/support/heterogeneity experiment still depends on real targets and CE outcomes. The registered statistical synthesis is pair/seed based and does not calculate instance-paired Monte Carlo uncertainty for the synthetic strata.

These are registered contracts and code paths, not executed outcomes. Before calling the redesign executable, the synthetic registry must declare the intended instance strata and denominators, retain all generator/solver failures, persist action-level metrics needed by the claims, and use a generator-conditional analysis keyed by instance. Do not infer a primary result from configured cell counts or diagnostic artifacts.

### Existing common-action zero-gap family (2026-09-25)

The code already contains a structural zero-gap construction: `_common_action_response` assigns one constant value to each block pair. Every admissible within-block permutation leaves that response matrix unchanged. An ignored POC selected a feasible nonzero fixed action for five generated `(2,2)` common-action worlds and checked all four maps; in every case the orbit and rectangular values matched exactly and `fixed_action_rectangularization_gap` was `0.0`. The POC is `docs/audit/pocs/common_action_zero_gap_check.py` with JSON output alongside it.

This corrects the claim that the project lacks a zero-gap generator. The gap is instead in wiring: the common-action executor persists robust/map-information metrics, not the fixed-action joint-map-versus-rectangular gap, and the current coupling table does not combine it as a zero-gap comparison stratum. A future candidate can reuse this established construction, add the relevant gap metric, and keep it distinct from random coupling-destruction controls. The five POC draws verify the structural property; they are not five independent inferential units or a sample-size basis.

### Coupling-label versus rectangular-gap consistency (2026-09-25)

An ignored POC regenerated ten `(2,2)`, support-2 instances for each existing coupling label at heterogeneity 1, asymmetry 0.5 and density 0.5, then recomputed the exact fixed-action gap with the production orbit and rectangular hull. All returned labels matched the requested construction. However, all ten `jointly_realizable` instances had a positive rectangularization gap (range `0.00035`–`0.01282`); the ten `incompatible` instances had gaps `0.00129`–`0.01539`, above the registered `1e-6` floor. Raw rows are in `coupling_label_gap_consistency.json`; the script is `check_coupling_label_gap_consistency.py`.

This is not a generator-label bug: `_classify_coupling` calls a case jointly realizable when one orbit map simultaneously minimizes the **importance-weighted response for each active action coordinate**. The rectangular hull minimizes each matrix entry independently over the orbit, which can be strictly smaller even when those coordinate-wise weighted minima share a map. Thus `jointly_realizable` does not mean “zero fixed-action gap,” nor is it a zero-gap negative control. Keep the label as a construction stratum if useful, but use the constant-within-block-pair common-action construction above as the structural zero-gap control, and report the exact gap directly for every sampled action. This POC tests label semantics only; it does not estimate a population difference between labels.

### Coupling-destroyed control invariant check (2026-09-25)

The current `coupling_destroyed_matrices` implementation independently shuffles every entry inside each source/target block pair. That preserves each block-pair entry multiset and mean, and it applies the same index permutation to paired lower/upper entries. It does **not** preserve a key invariant of the allowed same-block correspondence action: simultaneous row/column relabeling preserves the diagonal-entry multiset and the off-diagonal-entry multiset separately. Thus the control changes the within-block map response geometry along with label-entry association.

A two-node exact counterexample used `[[1, 7], [9, 3]]`. Under seed 0 the control preserved the whole-block multiset `{1,3,7,9}` and mean `5`, but changed the diagonal multiset `{1,3}` to `{3,9}`, the off-diagonal multiset `{7,9}` to `{1,7}`, and a fixed-action orbit response set from `{1,3}` to `{3,9}`. The same issue appeared on one generated jointly-realizable `(2,2)`, support-2 instance (heterogeneity/asymmetry/sparsity all `0.5`, seed 17, index 0): both within-block diagonal and off-diagonal multisets changed. Its fixed-action worst-map response changed from `0.0017448` to `-0.0011502`, and its fixed-action rectangularization gap changed from `0.0070341` to `0.0046541`. Reconstructing the producer's optimized metric on this same instance changed the selected exact robust action from `[0.25,0.25,0,0]` to `[0.25,0.21193,0,0]` and changed `robust_coupling_gap` from `0.0013123` to `0.0045711`; the rectangular action remained zero. These are a structural counterexample and one diagnostic generated instance, not population evidence. The reproducible ignored artifact is `docs/audit/pocs/coupling_shuffle_diagonal_invariant.py` and its JSON output.

The current control therefore cannot isolate a coupling-specific causal explanation: an observed difference may arise because the shuffle also changes same-block diagonal/off-diagonal values and the resulting admissible-map objective. The POC also implements a diagnostic shuffle that preserves these two value multisets separately inside same-block squares and preserves each cross-block entry multiset. On the same generated instance, all 20 tested shuffle seeds satisfy those checks, but the fixed-action rectangularization gap still ranges from `0.0013530` to `0.0079577` (11 distinct values at 12-decimal rounding); shuffle seed 0 changes it from the original `0.0070341` to `0.0079577`. One shuffle leaves the producer's optimized coupling gap unchanged from the original, which does not establish general invariance. Thus the entry-stratum constraints are necessary but do not preserve higher-order same-block arrangements or the orbit objective. Before using any destruction control as mechanism evidence, define its preserved invariants to match the claim and validate them on exact small orbits; keep both tested shuffles diagnostic unless a defensible claim-matched intervention is established.

### Instance replication and action contrast pilot (2026-09-25)

An ignored pilot sampled two registered generator labels (jointly realizable vs incompatible fixed-action minima), one small `[2,2]` block pattern, support 2, heterogeneity 1, asymmetry 0.5, and full response density. It generated 20 distinct `instance_index` values for each of three existing seeds per label (120 response operators total). All 120 cells generated successfully in about 10 seconds, and all 120 matrix hashes were distinct. This verifies that instance-level replication is implementable for this small stratum; it does not establish feasibility at larger blocks or across the full factorial.

On these pilot operators, the robust action had strictly higher worst-map value than the identity-point action in 55% of jointly realizable and 75% of incompatible instances; the corresponding rates against the rectangular action were 23% and 45%. Median robust regret was zero for the rectangular action in both labels, so there are many ties; mean regret was 0.0007 / 0.0020 (jointly realizable / incompatible), while mean point-action regret was 0.0043 / 0.0060. Distinct map-conditioned maximizing actions occurred in 68% / 88% of instances. These small-unit findings suggest action disagreement and map-dependent regret should be measured per generated operator, and that average gains may be concentrated in tails. They do not establish a material population effect: the label describes a fixed-action minimum-intersection property, not a randomized causal treatment, and only one generator stratum was sampled. Full vectors and cell outputs remain in ignored `synthetic_instance_variance.json`; script: `synthetic_instance_variance.py`.

For these 60-instance label strata, the SD of robust-minus-point worst-map payoff was 0.00575 (incompatible) and 0.00592 (jointly realizable); robust-minus-rectangular SD was 0.00338 and 0.00197. A simple normal-approximation calculation suggests about 128–135 instances per stratum for a 95% half-width of 0.001 on mean point-action advantage, and 15–44 for the rectangular contrast. These are planning diagnostics, not registered sample sizes: they come from one `[2,2]`, support-2, heterogeneity-1, asymmetry-0.5, density-1 setting and cannot size the positive-action boundary or other strata. Keep generated-instance variation separate from optimizer-seed variability; lock final instance replication by a pre-outcome precision analysis after strata and estimands are declared.

## Local external-data candidate screen (2026-09-25)

The additional local CIC candidates do not provide an application for FedORBIT's hidden fine-map interface. `CIC_IOT_Dataset2023` contains 309 class-folder CSVs plus 63 `Merged*.csv` files. The 40-column merged files carry explicit `Label` values; the bundled README says they are merged, shuffled, and split for convenient loading. They are data shards, not 63 clients or independent capture units, and the 40-feature export does not expose a device/client key. This can support ordinary labeled IDS comparisons, but not cross-device client inference from the merged shards or unknown-label-map claims. Local source: `raw/CIC_IOT_Dataset2023/CSV/README.pdf` and `CSV/CSV/README_CSV.pdf`; [official CICIoT2023 page](https://www.unb.ca/cic/datasets/iotdataset-2023.html).

Its README describes 40 smart-home devices overall and repeated device-specific interactions. It also describes separate 30-day whole-network idle/active captures and an attack arm: LOIC floods and camera RTSP brute-force attempts, three repeats per attacked device, captured on the attacker machine. This supplies useful device/activity context for a distinct within-testbed traffic profiling question, but its activity taxonomy is device-specific, the attacks target only some devices, and the threat capture point differs from device-local clients. The official README describes 30 active capture days, but the local manifest and raw folder contain only 24 active PCAPs. The local manifest contains the 28-device tables, archived idle/scenario/attack collections, and those 24 active PCAPs; it does not provide a shared client label map or evidence that each device is an independent organization. Do not promote it into the present study without a new estimand, active-capture completeness check, and attack capture-to-device support census. Local source: `raw/cic-iot-2022/Readme.txt`, `6-Attacks/Readme.txt`, `5-Active/Readme.txt`, `CSV files/README.md`, and `manifest.json`; [official CIC-IoT 2022 page](https://www.unb.ca/cic/datasets/iotdataset-2022.html).

Official source: [CIC IoMT 2024 dataset description](https://www.unb.ca/cic/datasets/iomt-dataset-2024.html).

A quick local screen initially found `CIC_IoT_DIAD_2024` has packet-based and flow-based feature exports, 180 and 132 CSV files respectively, with file sizes about 39.8 GB and 14.7 GB. The folder trees encode Benign plus attack categories, with many repeated capture-named files for DDoS and DoS. The packet README says rows are not labeled and labels must be assigned from file/category context. ## QAP cost-matrix indexing check (2026-09-26)

Derived the fixed-action assignment-variable quadratic matrix from the production objective and checked the indexing against every permutation at `n=4`. For `X[i,k]=1` iff map `P` sends `i` to `k`,

`w^T X L X^T alpha = sum_(i,j,k,l) w_i alpha_j L_kl X_ik X_jl`.

When the lifted cost matrix rows are assignment variables `(i,k)` and columns `(j,l)`, it is `(w alpha^T) ⊗ L`; therefore its matrix rank is `rank(L)` for nonzero `w, alpha`, although the QAP flow matrix `w alpha^T` itself has rank one. A fixed-seed `n=4` POC found flow rank 1, response rank 4, lifted cost-matrix rank 4, and maximum direct-vs-quadratic objective discrepancy `1.78e-15` over all 24 permutations. A separately constructed MAP-style outer-product cost matrix had rank 1. Script and JSON are ignored at `qap_cost_tensor_rank_check.py` and `qap_cost_tensor_rank_check.json`.

This distinction narrows the novelty comparison: Tian's thesis writes MAP as a rank-one Lawler cost matrix in the assignment-variable flattening, so its specialized MAP formulations do not directly cover a generic full-rank `L` in FedORBIT. The QAP-R1 publisher abstract does not expose enough indexing to determine whether its “rank-one cost matrix” means this Lawler flattening or a rank-one QAP flow matrix. If the former, the natural FedORBIT coefficient matrix is generically not rank one, but an equivalent transformed representation has not been ruled out; if the latter, the fixed-action subproblem is directly in the class. The exact article definition remains a publication gate. This algebra/implementation sanity check is not an empirical novelty result.

A related fixed-rank result does not close this gap. Punnen, Sripratak, and Karapetyan prove polynomial solvability for fixed-rank BQP01 cost matrices, where the model is `max x^T Q y + c x + d y + c0` over independent unconstrained binary vectors `x,y`. FedORBIT instead optimizes a QAP over permutation matrices, with row/column assignment constraints on `vec(X)`. The BQP01 result therefore does not apply to the lifted QAP merely because its coefficient matrix has rank `rank(L)`; using it would require a reduction that preserves both rank and the assignment-feasible set, and none has been established here. This is adjacent low-rank quadratic-programming prior art, not a direct method comparator. [Punnen et al., arXiv:1212.3736](https://arxiv.org/abs/1212.3736).

## Symmetric-response mapping to nonnegative QAP cost (2026-09-26)

For the fixed-action worst-map problem, the response subproblem minimizes `Q_L(P)=sum_ij F_ij L[P(i),P(j)]`, with `F=w alpha^T`. For symmetric zero-diagonal `L`, the minimizing version of the Kaya cost mapping is `D=C(J-I)+L`, where `C >= max(0,-min_offdiag(L))`; this yields a nonnegative symmetric zero-diagonal `D` and `Q_D(P)=Q_L(P)+C sum_(i!=j) F_ij`, a constant over every admissible map. The opposite sign `D=C(J-I)-L` maps response maximization to cost minimization, not the worst-map minimum. An exhaustive permutation POC checked block patterns `(2,2)`, `(3,3)`, `(4,4)`, `(5,5)` (4, 36, 576, and 14,400 maps), with symmetric zero-diagonal response and asymmetric rank-one flow. Maximum invariant error was `1.34e-15`; the minimizing map sets agreed within `1e-12` on every case. This establishes an algebraically matched symmetric subclass. It is not a direct solver comparison: `chpl` is unavailable in this environment and the external repository gives no prescribed run protocol. Ignored artifacts: `kaya_symmetric_cost_mapping.py` / `.json`.

A second POC passed symmetric zero-diagonal responses and rank-one asymmetric flows through both FedORBIT's production active-image separator and its generic SCIP QAP MILP, at `(4,4)`, `(5,5)`, `(6,6)`, and `(7,7)` blocks (8–14 nodes; restricted orbit sizes 576–25,401,600). All eight base/mapped SCIP solves certified; separator and SCIP values agreed within `4.5e-16`, and subtracting the invariant shift from the mapped objectives recovered the base response values. On these four single-seed cases, SCIP/separator time ratios were approximately 668x, 294x, 416x, and 474x for the base response, and 74x, 59x, 70x, and 81x after the nonnegative cost shift. This is a local generic-MILP proxy only: it does not benchmark Kaya, its branch-and-bound bounds, unrestricted injections, or end-to-end robust optimization; absolute times and one case per size do not establish scalability or novelty. Ignored artifacts: `kaya_proxy_symmetric_qap_scale.py` / `.json`.

The fixed-action flow is `F=w alpha^T`. If `alpha` has support at most `s`, then `F` has at most `ns` nonzero entries before excluding its diagonal. For symmetric `L`, the objective equals the one using symmetrized flow `(F+F^T)/2`; its undirected support has a vertex cover of size at most `s` and treewidth at most `s` (eliminate non-cover vertices first). Thus support 1 gives a star-flow/tree-QAP case, and configured support 2 gives a graph of treewidth at most two. This makes exact tree-QAP branch-and-bound and sparse-flow k-tree/TAP bounds especially close comparators ([Christofides and Benavent, 1989](https://pubsonline.informs.org/doi/10.1287/opre.37.5.760); [Milis and Magirou, 1995](https://doi.org/10.1016/0167-6377(94)00061-A)). This structural observation does not establish that a published solver accepts the original directed flow when `L` is asymmetric or FedORBIT's block-preserving subgroup; those assumptions remain to be checked.

This is a two-instance-per-shape engineering POC on very small configured cases, not an end-to-end robust-action comparison or a population result. SCIP's generic McCormick QAP MILP is not a substitute for the closest sparse-flow QAP algorithms, and sub-millisecond absolute separator times do not establish a practical or publishable advantage. It supports only that the implementation's sparse fixed-action specialization matches truth and is faster than this in-repository generic QAP path on these cases. A separate attempt to extend this generator-backed probe to `(4,4)` did not leave the jointly-realizable generator within a 20-second bound; that shape is outside the configured block patterns, and no solver timing is inferred from it.

## Cold-start collaboration POCs, N-BaIoT and Gotham (2026-09-26)

Ignored scripts/outputs under `pocs/`: `nbaiot_load.py`, `nbaiot_dup_check.py`, `nbaiot_coldstart_poc{,2,3,4}.py`, `nbaiot_fedavg_ae_poc.py` (discarded, see below), `nbaiot_poc6.py`, `nbaiot_poc7.py`, `poc8_selection_and_gotham.py`, `gotham_census.py`, `gotham_windows.py`, `gotham_poc.py`. Descriptive, single-seed-family pilots, not evidence. Setup: nine physical N-BaIoT devices as clients; benign-only anomaly detection with attacks used only for evaluation; local benign support of n contiguous windows (n from 30 to 1000); test benign is the chronologically later third with exact duplicates of the training third removed (up to 18.5% of the later third duplicated training rows on Danmini); attacks are Mirai/Gafgyt captures (3,000 sampled rows per attack file). Detector: Gaussian Mahalanobis with an OAS-shrunk covariance (closed form, exactly federable through moments) and a small autoencoder.
* Discarded pilot: a first FedAvg autoencoder pilot standardised its local baseline with pooled statistics, which already carries partner information, and reported no benefit. The confound was found by inspection and the pilot is not used.
* Cold-start failure is real and large: local-only AUROC (local standardisation) is 0.876/0.863 (Gaussian/AE) at n=30 and reaches 0.981/0.984 by n=1000.
* Information ladder (mean AUROC, n=30/100/300/1000, Gaussian): local 0.900/0.939/0.966/0.981; sharing only partner per-feature mean and standard deviation 0.984/0.985/0.990/0.993; partner rows with covariance (300 rows) 0.992/0.991/0.992/0.996; AE local 0.863/0.944/0.970/0.984 versus AE with shared marginal scale 0.984/0.984/0.993/0.998 versus AE trained on pooled rows 0.998/0.997/0.998/0.999. Marginal-only sharing recovers most of the pooled-data gain; partners' column-shuffled rows (destroying correlations, keeping marginals) performed as well as real partner rows (0.991 vs 0.992 at n=30, m=300). Nine of nine devices improve at n=30/100 under marginal sharing.
* Trivial local baselines matter: with no feature scaling the local baseline reaches 0.955/0.958/0.971/0.987, with a standard-deviation floor at 0.5 times the median 0.949/0.965/0.981/0.987. Federation therefore adds +0.014/+0.013/+0.005/+0.003 (8/9, 9/9, 8/9, 8/9 devices positive) beyond the best simple local normaliser, concentrated in Provision_PT_737E (+0.086); most of the conventional +0.084 cold-start gain at n=30 is recoverable locally.
* Dose: benefit saturates at 100 partner rows of marginal information (10 rows: 0.857; 30: 0.961; 100: 0.983) and decays for large partner covariance mass: at 30,000 partner rows the mean benefit is 0.109 versus 0.129 peak at n=30, and saturated devices are harmed (Ecobee -0.052, Philips -0.056 at n=100).
* Partner selection: with an oracle scale-profile similarity (full local benign) the two nearest partners give 0.995 at n=30 versus 0.982 for all eight and 0.953 for the two farthest; a similarity computed from the local rows themselves via model scores was unreliable at small n (near2 0.961 < all8 0.984). The deployable-selection variant with a consistent metric is not yet measured.
* Gotham2025 (78 simulated devices, 8 with attack traffic, 2-second window features from the packet CSVs; simulated testbed, not physical devices): local models are already saturated (AUROC 0.995-0.999 at n=10-100); sharing marginals is neutral to slightly positive (0.999 at n=30), while pooling covariance at n=10-30 is harmful (0.838/0.881 versus 0.996/0.995). This is the boundary regime.
* Predictor screen: gain correlates almost mechanically with local headroom (Spearman -0.65 to -0.95); an attack-free split-half scale-instability signal is weak (Spearman -0.04 to -0.38); an oracle scale-mismatch diagnostic (|log sd_local/sd_full|) correlates +0.37 overall. Predictor claims stay exploratory.
* Rejected earlier: CIC-IoT-2022 (physical devices but profiling data; attack pcaps on a few devices), Mon(IoT)r (no security labels), EMBER2024 file-type silos, LAMDA markets, ToN modalities.

### Newly identified external physical cohort: crowdsensing malware dataset (2026-09-30)

Feng et al. report eight physical Raspberry Pi clients (six Pi 3, two Pi 4), one benign condition and eight malware conditions, with 30-second behavioral windows from six system dimensions. This is the strongest newly identified candidate for a separate external replication of the cold-start information-channel experiment: it has explicit device keys, benign-only support is possible, and attacks are available for evaluation on those same devices. It is a separate testbed and malware cohort from N-BaIoT, not a broad deployment sample. The article reports 342,106 records from 288 monitoring hours and releases a 32-feature subset plus a 687-feature pre-selection representation and raw logs through Science Data Bank ([dataset paper](https://www.nature.com/articles/s41597-026-07155-w); [data record](https://doi.org/10.57760/sciencedb.25380); [processing repository](https://github.com/Cyber-Tracer/iot-feature-engineering)).

This is a candidate, not yet validated input. The released 32-feature set is label-informed (selected using Chi-squared, ANOVA F, and mutual information across class labels) and globally min-max scaled, so it must not be used for a benign-only detector claim. The 687-feature representation is the preferred path only if the dataset package confirms it is available with original row order and stable device/condition identifiers; reconstruct scaling from benign support and preserve the published feature construction. The public record describes rows as time windows but organizes files by device and label, and the inspected processing repository shuffles rows after scaling. Therefore file order cannot be presumed chronological. The published data contract has an unresolved internal arithmetic inconsistency: the article says each of eight devices ran nine conditions for four hours per device-condition (288 aggregate device-hours), and describes each row as one device's 30-second snapshot. Those statements imply 34,560 rows (8 × 9 × 4 × 120), while the paper reports 342,106. Missing windows could lower the expected count, not explain this tenfold excess; the meaning of the hour or row unit must differ from at least one stated description. This does not prove the released files are wrong, but it prevents treating their time-window interpretation as verified. Eight author-repository per-device 30-second merge notebooks have stored outputs totaling 349,367 rows (40,183; 46,663; 44,223; 48,241; 76,826; 25,676; 28,869; 38,686), close to the paper's 342,106 records. The notebook code resamples sources to 30-second bins and outer-merges by timestamp, but these stored variants have only 286–306 columns rather than the paper's 687-feature representation, so direct provenance from these outputs to the released data is unverified. The separate collection README documents 5-second and 10-second monitor cadences, and its controller starts the selected monitor services concurrently for one requested duration; different raw sampling rates alone therefore do not explain a tenfold excess if a row is one merged 30-second device-time window. The preparation script drops incomplete rows and shuffles; that could explain a count decrease but not the excess. If every row is one device-time window, the two counts represent about 2,911 and 2,851 aggregate device-hours, respectively, versus 288 stated hours. The release metadata or authors must reconcile what the 288-hour figure counts and how published rows map to device-time windows. The published article gives the DOI and a record URL with dataset ID `0151eff3132541e2852a10ed65e0991f`; the ScienceDB record and Swagger UI returned empty browser extractions, while its advertised OAI-PMH endpoint returned XML that the browser tool could not parse. The article’s private reviewer-access URL (`https://www.scidb.cn/en/s/YJbeia`) was also inaccessible through the browser. ScienceDB’s [Terms of Service](https://www.scidb.cn/en/about/terms) confirms that the platform offers Open API and OAI-PMH services and says reuse/redistribution must follow the corresponding dataset license. This is platform policy, not evidence of this record’s license. The Open API specification and exact DOI-based OAI-PMH GetRecord remain inaccessible through the available browser path. Shell DNS also cannot resolve `www.scidb.cn` in this environment. Thus file names, downloadable package versions, license, and row-level metadata remain unverified; this is an access-path limitation, not evidence that the package is absent. Check the [author processing notebooks](https://github.com/Cyber-Tracer/iot-feature-engineering/tree/main/data_merg), [training preparation script](https://github.com/Cyber-Tracer/iot-feature-engineering/blob/main/training/create_fedstallar_dataset.py), [collection README](https://github.com/Cyber-Tracer/MalwareDetectionDataset/blob/main/README.md), [collection controller](https://github.com/Cyber-Tracer/MalwareDetectionDataset/blob/main/controller/collect.py), and package metadata before making data-coverage claims. Before modeling, verify package contents, time/order provenance, per-device benign row counts and condition support, consistent feature schema across devices, duplicates, missingness, and whether support can precede benign test rows without label-based selection. If there is no recoverable chronology for the benign rows, this cohort cannot validate the current support-to-later-test estimand; it could support only a separately registered non-temporal replication. Do not pool its moments with N-BaIoT because feature schemas differ.

**Highest-value next step:** obtain the Science Data Bank package metadata/file list and a small, non-modeling schema/chronology census. Advance to a prelocked independent validation only if the 687-feature or raw-log path avoids label-informed feature selection, preserves a defensible benign chronology, and supplies adequate within-device support and attack coverage. Then prospectively test local mean + partner scale against local, shared marginals, and partner mean + local scale, with device-level paired inference, AUROC and predeclared low-FPR outcomes, and no use of N-BaIoT outcomes for design tuning. Until those gates pass, external physical validation remains unestablished.

## Follow-up cold-start mechanism search (C101–C106; exploratory, 2026-09-27–30)

These POCs reused production OAS scoring, identical target supports/test rows where stated, and the fixed `shared-marginals` baseline. They did not change the completed confirmatory protocol or select endpoints after its results. Scripts and raw outputs remain in ignored `docs/audit/pocs/`; the results needed to interpret candidate dispositions are consolidated in this file.

* **C101–C102, empirical calibration and OAS decomposition.** A lower-tail peer pseudo-target gate reduced peer borrowing from about 70–77% to 8–11%, but yielded 0/9 positive device-mean AUROC cells and substantial low-FPR loss versus shared marginals. C102 replayed the OAS decomposition on the exact C101 supports: changing the raw-space diagonal shrinkage target explained nearly all local-to-peer scale effect, while changing OAS intensity alone had negligible AUROC effect. The peer-target arm still trailed shared marginals on mean AUROC at every support size; lower-tail pAUC harms remained. This identifies the scorer mechanism, not a useful selection rule.
* **C103–C104, threat-matched local scale and component ablation.** In a controlled spherical Gaussian mean-shift mixture, true-covariance Mahalanobis ranking is optimal for that threat, and target-local scale sometimes modestly beat shared marginals under covariance mismatch. Gains faded with support and had negative lower tails. C104 then ran a four-way center/scale decomposition on the same 30 deterministic support windows, attack rows, and benign test rows per physical device/support used in C101/C102 (4,320 paired method rows; production OAS scorer). Keeping the target-local mean while borrowing partner scale recovered about 90%, 96%, 90%, and 95% of the shared-marginals-versus-local AUROC gap at n=30/100/300/1000; it still trailed shared marginals by mean AUROC 0.00836/0.00180/0.00295/0.00056, with only 2/9, 2/9, 1/9, and 3/9 positive device means. Its standardized pAUC(.01) deltas also remained negative (−0.01059/−0.00990/−0.00875/−0.00476). The opposite crossing, partner mean with target-local scale, lost 0.07686/0.04232/0.02005/0.00542 mean AUROC. This supports the exploratory mechanism that scale sharing carries most of the observed ranking gain; it does not establish a confirmatory scale-only effect or a no-harm rule, and its low-FPR tail remains a problem. The synthetic threat result therefore did not transfer to the observed attack mixture.
* **C105–C106, two-sided scale-compatibility gates.** A Gaussian variance test looked modestly positive on the synthetic threat but depended on known peer variances and retained negative paired tails; it failed on real N-BaIoT data. Replacing its parametric reference with empirical peer pseudo-target windows selected local scale on only 7.4–9.1% of features, improved over local-only, but still lost to shared marginals: mean AUROC −0.0221/−0.0141/−0.0078/−0.0010 and standardized pAUC(.01) −0.0737/−0.0700/−0.0441/−0.0203 over n=30/100/300/1000. The pseudo-target reference is dependent/nonexchangeable, and action frequency is not a detector-risk certificate.
* **Earlier branches C1–C100.** Robust/local scale, cross-fitted predictive loss, empirical-Bayes and VASH-style shrinkage, peer-correlation targets, covariance-risk weights, threat-mixture selectors, source-attack transfer, and source selection/fusion were screened. No tested benign-only scale selector beat fixed shared marginals with reliable lower-tail/device behavior. Source-attack transfer sometimes improved aggregate AUROC but incurred device/family tails, higher payload, or development/evaluation reuse; benign-only source similarity and pseudo-target validation did not reliably rank transfer utility. Those failures reject the tested candidates, not all possible transfer methods.

**Disposition:** no algorithm is promoted. The defensible active result remains the original empirical information-channel decomposition, whose novelty boundary and nearest methods are reassessed in `Scientific Decisions.md` and `Reviewer Audit.md`. POC metrics are exploratory and must not be reported as confirmatory manuscript results.
